# ai-lib

Two things: (1) the shared player UI every resource draws through the lib (notification cards, the progress bar and its cancel key, the prompts on the right and the interaction key, menus, input dialogs, minigames), as ai-lib's own client script (`resource/ui`) and page (`web/`); (2) the `@aicore-fivem/lib` helpers for resources that do not bundle the npm package, loaded like ox_lib and running in the resource that loads them: Lua through `shared_script '@ai-lib/init.lua'` (global `aiLib`), JavaScript through `client_script '@ai-lib/dist/client.js'` / `server_script '@ai-lib/dist/server.js'` (global `aiLib`). The UI runs without ai-core (owner decision: someone can use ai-lib alone); the lib helpers that forward to ai-core (players, money, inventory layer...) need it.

## Decisions

- The shared player UI lives here, not in ai-core (owner decision, 2026-10-31): `resource/ui` (bundled as `dist/ui.js`, the only script ai-lib runs: `fxClientScripts`) answers the client exports `Notify`, `ShowProgress` / `HideProgress`, `ShowPrompt` / `HidePrompt`, `OpenMenu`, `OpenInput`, `OpenMinigame`, `CloseDialog` (typed `AiLibClientExports`), the server event `LIB_UI.notifyEvent` and the server flows' callbacks `LIB_UI.progressForCallback` / `minigameForCallback`; answers go back on `MENU_EVENTS.*` / `LIB_UI.promptPressedEvent` / `LIB_UI.cancelProgressEvent` (all `ai-lib:*` names, `@aicore-fivem/shared` `ui.ts`). The keybinds keep their old names (`aicore_interact`, `aicore_cancel_progress`) so players' own bindings survive. The page sits above other NUI pages (`SetNuiZindex(100)`: a menu over ai-core's character screen); focus is per resource, so ai-lib taking and giving back the focus never touches another resource's screen. ai-core keeps the dialogs that need its systems (the admin item picker, the keys screen) and the panel's settings the UI follows (`ai:interaction`, keybind defaults), read when ai-core runs, defaults otherwise. No `ai-core` dependency in the manifest.
- Menu icons: `web/src/lib/icons.ts` (Font Awesome names a menu item may use); a name missing there shows a dot.
- Build: the template's `client` / `server` bundles stay import bundles (`fxImport: true`); `tsdown.config.ts` adds the `ui` bundle; `build` runs the web build first and wraps both client bundles with `aicore-client-errors`. Browser preview `bun run webdev` with `?view=menu|notify|prompt|skillcheck|lockpick`.
- An import file, not exports (owner decision): the code runs inside the resource that loads it, so points, keybinds, commands and callbacks belong to that resource and go with it; no registry, no start / stop tracking.
- JavaScript side: `fxImport: true` in `package.json` (bundles listed in `files`, no script run here); the whole lib (shared + the side's helpers) on `aiLib`.
- Lua side: a port, not a wrapper around the JS bundle (Lua cannot load JavaScript). `init.lua` loads `lua/<side>/<name>.lua`, else `lua/shared/<name>.lua`, on first use of `aiLib.<name>`; modules use the same wire formats as the TypeScript lib (callbacks, keybind announce / key events, prompts, the `ai:interaction` style, vehicle state bags), so Lua and TypeScript resources answer each other. Async calls (`triggerServerCallback`, `menu.show`, `progress`, `spawnVehicle`) wait with `Citizen.Await` / `Wait`: call them from a thread.
- Lua `Points` matches the TypeScript one: prompt and target modes, enter / exit, a blip, an NPC (`ped`, a `LocalPed` with the target option on it) and model points (`addModel`, `vehicles = true` for vehicle models). One 500 ms check for the resource's points and one for its model points, each running while such points exist; `Zones` has one job for the resource at the shortest zone interval, each zone at its own interval.
- Periodic work in the Lua modules runs on `aiLib.every` (`lua/shared/every.lua`): one scheduler thread per resource that sleeps until the next due job and ends while none is active, like the TypeScript `every`. Never a module's own `CreateThread` + `Wait` loop; blocking waits of a caller's flow (`waitFor`, `progress`, the ground search) stay in the caller's thread.

## Contracts

- Lua (`aiLib.`): shared `every` (`job:set(active)`, `job:stop()`, `job.running`), `waitFor`, `formatText`, `locale`, `fail`, `numbers` (`round`, `groupDigits`, `headingTo`), `stripGameText`; client `cache` (+ `cache.onChange`), `playerData` (`get`, `onChange`), `notify`, `progress` (`anim` / `scenario`, `canCancel` with ai-lib's cancel key, `whileDead`, `freeze`, `disable`; `progress.cancel()`, `progress.isRunning()`), `menu.show` (with `{ onHover, onToggle }` listeners) / `menu.input` (`input`) / `menu.itemPicker` (`itemPicker`, ai-core's) / `skillCheck` / `lockpick`, `keyHints`, `showPrompt` / `hidePrompt` / `onPromptPressed`, `Points.new()` (+ `addModel`, `addVehicle`), `Zones.new()`, `LocalPed.new()` (`attach`, `seat`), `Blips.new()` / `Blips.create()`, `Keybind.new()` (`hint`, `icon`, `hintLabel`), `player` (`coords`, `heading`, `distanceTo`, `freeze`, `teleport` with `ground = 'find'`, `playAnim`, `stopAnim`), `fadeOut` / `fadeIn`, `waitForEntity`, `nearestVehicle` (+ `filter`), `nearestPlayer`, `onShot`, `callAction`, `controls` (+ `disableAll`), `hud`, `gestures`, `radial` (`add`, `remove`, `refresh`), `inventory`, `world`, `appearance` (`apply`, `read`), `requestModel` / `requestAnimDict` / `requestAnimSet` / `requestPtfxAsset` / `requestTextureDict` / `requestWeaponAsset`, `pedHeadshot`, `locationName`, `vehicleLabel`, `groundZ`, `raycast`, `triggerServerCallback`, `onServerCallback`, `onServerEvent`; server `progressFor` (waits, server-timed), `minigameFor` (waits: 'won' | 'lost' | 'broken'), `onClientCallback` (rate, lock, ace), `onClientEvent`, `triggerClientCallback`, `notify`, `addCommand`, `spawnVehicle`, `playersNear`, `playersNearEntity`, `nearestVehicleTo` (+ `filter`), `nearestPlayerTo`, `vehicleFromNet`, `vehicleNearPlayer`, `onCharacter`, `online` (+ `gangs`, `jobGrade`, `gangGrade`), `RateLimit.new(count, windowMs)`, `isAdmin`, `aiLog`, `inventory`, `vehicleKeys`, `phone`, `dispatch`, `world`, `prison` (`jail`, `release`, `timeLeft`), `appearance` (`get` waits, `provider`). Not on the Lua side: the admin panel (`AdminPanel`, `AdminWorld`), `PendingActions` / `PlayerMap` / `Cooldowns` / `KeyedCooldowns` (Lua tables do it; no Lua flow needs them yet), `online`'s member sets (Lua `online` asks ai-core's exports per call), the strict input readers, position helpers (Lua has vector math), state bag classes (Lua reads `Entity(e).state` itself, the server writes), vehicle props readers and the database (Lua resources use ai-mysql's oxmysql API). Types: the `AiLib` class in `init.lua`.
- ai-core carries a copy of the Lua side in `bridge/lib/` (its bridge starts before ai-lib), refreshed from this folder on every ai-core build; `init.lua` loads from `AiLibResource` / `AiLibRoot` when the host sets them. Edit the modules here, never the copy.
- JavaScript: `aiLib` = the lib's `/shared` plus `/client` or `/server` (`.claude/rules/lib.md`).

## Entry points

- UI host `resource/ui/` (notify, prompts, dialogs, minigame, progressFor) and its page `web/src/` (`main.tsx`, `features/`).
- Lua loader `init.lua`, modules `lua/{shared,client,server}/`; JS entries `resource/client/index.ts`, `resource/server/index.ts`.
